# 项目3：API 到 Coze 闭环测试记录

## 一、测试目标

本次测试用于验证“门店评论分析与自动回复 Agent”项目在 API 改造后的本地闭环流程是否可用。

测试重点包括：

1. FastAPI 是否能够接收门店评论 CSV 文件；
2. Python / Pandas 是否能够正确完成评论统计、差评筛选和问题分类；
3. API 是否能够生成适合 Coze / Dify 使用的 Markdown 输入文本；
4. Coze 是否能够基于 API 生成的 Markdown 文本输出门店经营分析周报；
5. Coze 输出是否符合经营分析要求和回复边界规则。

本次测试验证的是本地半自动闭环流程，即：

```text
上传 CSV 文件
↓
FastAPI 接收文件
↓
Python / Pandas 分析评论
↓
API 生成 Markdown 输入文本
↓
复制 Markdown 到 Coze
↓
Coze 生成门店经营分析周报
```

## 九、存在的小问题

本次测试中发现一个轻微问题：

API 的分类结果中，“产品质量”分类数量为 6 条，而早期脚本版本中该分类数量曾出现过不同结果。

原因可能是：

1. 当前分类逻辑基于关键词规则；
2. “咖啡”“拿铁”“口感”等关键词会优先命中产品质量；
3. 关键词配置和分类顺序会影响最终分类结果。

该问题不影响本次闭环流程测试，但说明当前评论分类仍属于规则分类，复杂语义下可能存在误判。

后续可优化方向：

- 调整关键词命中优先级；
- 引入多标签分类；
- 接入大模型进行语义分类；
- 增加人工校正机制。

## 十四、面试表达总结

本项目原始版本是一个门店评论分析脚本，主要通过 Python / Pandas 读取 CSV 文件，完成评分统计、差评筛选、问题分类，并生成给 Coze 使用的经营分析输入文本。

在后续 API 改造中，我使用 FastAPI 将评论分析能力封装成接口，支持通过 JSON 或 CSV 文件上传的方式调用。为了让 API 输出更适合 AI 工作流使用，我进一步增加了 Markdown 文本生成接口，使系统能够在上传 CSV 后自动生成可复制到 Coze / Dify 的分析输入。

本次闭环测试中，我完成了从 CSV 上传、API 分析、Markdown 生成，到 Coze 经营周报生成的完整本地流程。这个过程让我理解了脚本、API、JSON、Markdown 和 AI 工作流之间的关系，也让我认识到真实 AI 应用落地不仅要完成模型输出，还要考虑数据输入、接口调用、格式转换、边界控制和最终交付效果。
