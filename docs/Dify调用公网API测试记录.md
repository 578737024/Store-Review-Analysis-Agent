# 项目3：Dify 调用公网 API 测试记录

## 一、测试目标

本次测试用于验证“门店评论分析与自动回复 Agent”在完成 API 工程化改造后，是否可以被 Dify 工作流通过公网 API 调用，并由 Dify 的大模型节点自动生成门店经营分析周报。

本次测试重点验证：

1. FastAPI 服务是否已成功部署到公网；
2. Dify 是否能够通过 HTTP 请求节点访问公网 API；
3. Dify 是否能够获取 API 返回的 Markdown 数据；
4. Dify 的 LLM 节点是否能够基于 API 返回内容生成经营分析周报；
5. 最终报告是否符合门店运营分析要求和回复边界规则。

---

## 二、测试背景

本项目原始版本是一个本地 Python 评论分析脚本，主要通过读取 CSV 文件完成：

- 评论数量统计；
- 平均评分计算；
- 好评 / 中评 / 差评分类；
- 差评筛选；
- 问题类型分类；
- 生成 Coze / Dify 可用的 Markdown 输入文本。

后续项目进行了 API 工程化改造：

1. 使用 FastAPI 封装评论分析能力；
2. 支持 JSON 请求调用；
3. 支持 CSV 文件上传；
4. 支持返回结构化 JSON；
5. 支持返回 Markdown 分析文本；
6. 使用 Render 将 FastAPI 服务部署到公网；
7. 使用 Dify HTTP 请求节点调用公网 API；
8. 使用 Dify LLM 节点生成经营分析周报。

## 八、Step 3：Dify LLM 节点生成经营分析周报

LLM 节点任务

LLM 节点读取 HTTP 请求返回的 bodyString，从中识别 API 返回的 markdown 字段，并基于 Markdown 中的数据生成门店评论经营分析周报。

LLM 节点提示词核心要求

LLM 节点要求：

1. 只基于 API 返回结果中的 Markdown 数据分析；
2. 必须引用具体数据；
3. 不输出报告日期占位符；
4. 不虚构门店已经完成整改；
5. 不承诺退款、赔偿、免单；
6. 不使用“杜绝”“保证不会再发生”等绝对化表达；
7. 商家回复要真诚、克制、不甩锅；
8. 输出结构适合门店负责人查看。

Dify 输出结果摘要

Dify 最终生成了结构化经营分析周报，包含以下模块：

```text
【一、本周评论整体概况】
【二、差评主要问题】
【三、问题原因分析】
【四、优先改进建议】
【五、典型差评回复建议】
【六、下周运营重点】
【七、总结】
```

输出中正确识别了以下数据：

| 指标     | 结果             |
| ------ | -------------- |
| 评论总数   | 4              |
| 平均评分   | 2.5            |
| 好评数量   | 1              |
| 中评数量   | 0              |
| 差评数量   | 3              |
| 差评占比   | 75.0%          |
| 差评主要问题 | 等待时间、配送物流、服务态度 |

## 十一、当前局限

本次 Dify 工作流测试仍存在以下局限：

1. 当前测试使用的是 4 条评论 JSON 数据，不是完整 20 条 CSV 数据；

4. 当前分类逻辑仍基于关键词规则，复杂语义下可能存在误判；
5. Dify LLM 输出仍需要提示词约束，否则可能出现过度承诺、占位符或虚构整改事实；
6. Render 免费实例存在冷启动问题，长时间不访问后首次请求可能变慢。

## 十五、面试表达总结

本项目最初是一个本地门店评论分析脚本，我使用 Python 和 Pandas 读取评论 CSV，完成评分统计、差评筛选、关键词分类，并生成给 Coze 使用的经营分析输入文本。

后续我对项目进行了 API 工程化改造，使用 FastAPI 将评论分析能力封装成接口，并通过 Render 部署到公网。这样外部系统就可以通过 HTTP 请求调用我的评论分析服务，而不是只能在本地运行 Python 脚本。

在 Dify 工作流中，我使用 HTTP 请求节点调用 Render 上的 FastAPI 接口，获取 API 返回的 Markdown 分析文本，再由 Dify 的 LLM 节点生成门店经营分析周报。这个流程实现了从数据处理、接口调用到 AI 报告生成的自动化闭环。

通过这个项目，我理解了本地脚本、API 服务、公网部署和 AI 工作流之间的关系，也学会了如何把一个 Python 数据处理脚本升级成可以被 Dify 调用的 AI 应用服务。
