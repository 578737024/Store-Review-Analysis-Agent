# 项目3：门店评论分析与自动回复 Agent 面试讲解稿

## 一、30秒版本

这个项目是我基于 Python + Coze 做的门店评论分析与自动回复 Agent。

项目的核心流程是：先用 Python 读取门店评论 CSV，完成评分统计、差评筛选、评论分类和问题分布统计，再把结构化结果输入 Coze，由智能体生成门店经营周报、改进建议和典型差评回复。

我做这个项目的目的，是想模拟一个真实门店运营场景：门店每天会收到很多评论，如果人工逐条看效率比较低，所以我用 Python 先做数据处理，再用 AI 生成经营分析和回复建议。

---

## 二、1分钟版本

这个项目是一个门店评论分析与自动回复 Agent，主要面向咖啡店、餐饮门店这类本地生活场景。

项目分成两部分：Python 部分和 Coze 部分。

Python 部分主要负责读取评论 CSV，统计评论总数、平均评分、好评数量、中评数量和差评数量；然后筛选评分小于等于 2 分的差评；再通过关键词规则把评论分成配送物流、等待时间、服务态度、环境卫生、产品质量等类别；最后生成一份结构化的经营分析输入文件。

Coze 部分负责根据 Python 输出的结构化数据生成门店评论分析周报，包括本周评论概况、差评主要问题、原因分析、优先改进建议、典型差评回复和下周运营重点。

这个项目不是直接把原始评论丢给大模型，而是先用 Python 做结构化数据处理，再让 Coze 做分析和生成。这样输出会更有数据依据，也更接近真实业务流程。

## 三、3分钟版本

这个项目叫门店评论分析与自动回复 Agent，是我基于 Python + Coze 做的一个 AI 应用项目。

项目背景是：门店在日常经营中会收到很多用户评论，比如出餐慢、外卖撒漏、服务态度不好、环境卫生不及时、产品口味不稳定等。如果完全靠人工查看评论，效率比较低，而且很难快速发现差评主要集中在哪些问题上。

所以我设计了一个流程：先用 Python 对评论数据做结构化处理，再把统计结果交给 Coze 生成经营分析和商家回复建议。

整个项目主要有几个步骤。

第一步是读取评论 CSV。评论数据包含 review_id、date、store_name、rating、content、category 这些字段。

第二步是做基础评分统计，包括评论总数、平均评分、好评数量、中评数量、差评数量，以及好评、中评、差评占比。

第三步是筛选差评。我把评分小于等于 2 分的评论定义为差评，并导出差评明细表。

第四步是评论分类。我先用关键词规则做基础分类，比如外卖、漏、少送归为配送物流；等、排队、很久归为等待时间；服务员、态度、冷淡归为服务态度；桌面、地面、脏归为环境卫生。

第五步是统计问题分布。系统会统计全部评论和差评中的问题类型数量和占比。比如这次测试中，差评主要集中在配送物流、等待时间和环境卫生三个方向，每类都是 2 条，各占差评的 25%，三类合计占差评总数的 75%。

第六步是生成 Coze 输入文本。Python 会把基础统计、分类统计、差评明细整理成 markdown 文件，然后复制到 Coze 里。

最后，Coze 会基于这些结构化数据生成门店经营周报，包括整体概况、差评主要问题、原因分析、优先改进建议、典型差评回复和下周运营重点。

这个项目里我特别注意了 AI 输出边界。比如商家回复不能随便说“我们已经整改”“已经更换杯盖”“已经安排专人处理”，因为输入数据里没有这些事实。所以我在 Prompt 里加入了边界规则，要求智能体只能说“会反馈”“会检查”“会优化”，不能虚构已经完成的措施，也不能承诺退款、赔偿、免单。

这个项目目前还是学习型和演示型项目，数据集比较小，分类也主要基于关键词规则，复杂语义下可能会有误判。后续可以优化成更大的数据集，引入 AI 语义分类，增加图表输出，或者用 Streamlit 做一个可视化页面。

通过这个项目，我主要锻炼了 Python 数据处理、Pandas 使用、业务场景拆解、评论分类规则设计、Prompt 结构化设计，以及把数据统计结果转化成 AI 经营分析报告的能力。

# 面试官可能追问的问题

## 1. 这个项目和直接让 ChatGPT 分析评论有什么区别？

直接让 ChatGPT 分析原始评论，可能会比较泛，而且缺少统计依据。

我这个项目先用 Python 做了结构化处理，包括评分统计、差评筛选、分类统计和问题分布统计，再把结果输入 Coze。这样 Coze 输出经营周报时，会基于明确的数据，比如差评数量、差评占比、问题类别占比，而不是凭感觉总结。

## 2. 你为什么不用大模型直接分类评论？

当前版本我先用了关键词规则分类，因为它简单、可控、容易解释，也方便我验证整个项目流程。

但它确实有局限，比如“出餐也快”可能因为命中“出餐”而被分到等待时间。后续可以改成 AI 语义分类，或者规则分类 + 人工校验，提高准确率。

## 3. 这个项目里 Python 主要做了什么？

Python 主要做数据处理部分：

1. 读取 CSV；
2. 检查字段是否完整；
3. 统计评论总数、平均评分、好评/中评/差评数量；
4. 筛选评分小于等于 2 分的差评；
5. 根据关键词规则给评论分类；
6. 统计各类问题数量和占比；
7. 生成给 Coze 使用的 markdown 分析输入。

## 4. Coze 在这个项目里做了什么？

Coze 主要负责生成分析报告和回复话术。

它接收 Python 生成的结构化输入，然后输出门店经营周报，包括整体概况、差评问题、原因分析、改进建议、典型差评回复和下周运营重点。

所以 Python 负责“算清楚”，Coze 负责“讲清楚”。

## 5. 你怎么控制商家回复不要乱承诺？

我在 Prompt 里加了回复边界规则。

比如不能承诺一定退款、赔偿、免单，也不能说门店已经完成整改。因为用户给的数据只是评论统计，并没有提供真实处理结果。

所以回复里只能表达歉意、说明会反馈、会检查、会优化，不能虚构已经采取的措施。

## 6. 这个项目最大的不足是什么？

最大不足有三个：

第一，数据量比较小，目前只有 20 条模拟评论。

第二，评论分类是关键词规则，复杂语义下可能不够准确。

第三，当前 Python 和 Coze 是分开的，需要手动复制 Python 生成的 markdown 到 Coze，还没有实现完全自动化。

后续可以扩展成 100 条以上数据，加入 AI 分类，增加图表输出，或者用 Streamlit 做可视化页面。

## 7. 这个项目体现了你什么能力？

它主要体现了我几个能力：

1. 基础 Python 和 Pandas 数据处理能力；
2. 能把评论数据转成结构化分析结果；
3. 能根据业务场景设计分类规则；
4. 能用 Coze 搭建经营分析类 Agent；
5. 能在 Prompt 中加入边界控制，避免 AI 编造和过度承诺；
6. 能把 AI 应用到门店运营复盘和客服回复场景中。

## 8. 如果真实门店要用，还需要补什么？

如果真实门店要用，需要补几个部分：

1. 接入真实评论数据来源，比如美团、点评、外卖平台或门店后台；
2. 增加更大的数据量；
3. 优化分类方式，从关键词规则升级到 AI 语义分类；
4. 增加人工审核机制，尤其是商家回复不能直接自动发布；
5. 增加可视化图表和周期性报告；
6. 建立数据更新和历史趋势对比机制。
